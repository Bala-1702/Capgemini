In SQL, a primary key uniquely identifies each row within a single table, while a foreign key is a column (or columns) in one table that references the primary key of another table, establishing a link.
 
alter table person add foreign key(car_id) references car(id); -> we can foreign key constraint like this.
 
alter table person add column car_id int references car(id) unique; -> we can add constaint while adding new column to table.
 
If we remove one attribute from the primary key and it still to be act as a primary key(uniquely identifies row) then the previous key is not minimal. 
 
If you can’t remove any attribute from the key without breaking uniqueness, then the key is minimal.
 
 
Natural keys are unique identifiers from real-world data (like email or SSN) with business meaning, while surrogate keys are artificial, system-generated, meaningless values (like auto-increment IDs) used for stable identification.
 
Candidate key - minimal set of columns that uniquely identifies each row.
Super key - Set of columns that uniquely identifies each row, the set may be minimal or not minimal.
Composite key - tow or more columns that uniquely identifies each row.
 
Performing calculations on a group of data to return a single summary value is called an aggregate function (or aggregation).

A view in SQL is essentially a virtual table that is defined by a SQL query. Unlike a regular table, a view does not store data physically. 

  Instead, it dynamically retrieves data from one or more underlying tables (or even other views) whenever you query it.
 
create view Luxury as select * from
  select make,model,price,
       CASE
             when price>70000 then 'Luxury'
             when price between 50000 and 70000 then 'Premium'
             else 'Budget'
      end as Category
  from car) t
where category = 'Luxury' Limit 50;
